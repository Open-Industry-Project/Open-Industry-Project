Connection guides

Step-by-step guides for connecting a real PLC, SCADA or HMI to the simulator. Three guides are tested by following them in the desktop app: Modbus against OpenPLC, OPC UA against an OPC UA client (node-opcua), and S7 against a stand-in S7 CPU in this repository. The PLC-server, SLMP and ADS guides are not tested this way.

A PLC polls the simulator (Modbus TCP)

The simulator serves its sensors and motors on a Modbus TCP server, like a remote I/O rack, and your PLC's master reads and writes them. The example uses OpenPLC.

A PLC that serves its I/O (Modbus TCP or OPC UA)

The simulator connects to the PLC's Modbus server device by address, or to its OPC UA server by variable name.

An S7-1200 or S7-1500 (S7 PUT/GET)

The simulator reads and writes the CPU's inputs, outputs, memory and data blocks at the scene's own addresses. Covers the setting the CPU needs before it allows PUT/GET.

A MELSEC PLC (SLMP)

The simulator reads and writes the CPU's X, Y, M and D devices at the scene's own addresses, over the 3E frame every Q, L, iQ-R and iQ-F CPU answers.

A TwinCAT PLC (ADS)

The simulator reads and writes the PLC's variables by name through the TwinCAT router on its own PC, with the route a PLC on another computer needs.

A SCADA or HMI on the line (OPC UA)

The program keeps running in the simulator, which publishes its variables on an OPC UA server for your SCADA, HMI or any OPC UA client.
