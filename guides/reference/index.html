3. The simulator as a Modbus TCP server

In the dialog this is "The PLC polls the simulator". Each I/O address lands on one Modbus point by a fixed rule. The PLC reads the inputs (%I) and writes the outputs (%Q). Addresses are 0-based protocol addresses; the unit ID is ignored.

AddressModbus pointThe PLC
%IXb.nDiscrete input b×8 + nreads it (FC2)
%QXb.nCoil b×8 + nwrites it (FC5 / FC15)
%IWnInput register nreads it (FC4)
%QWnHolding register nwrites it (FC6 / FC16)
%IDnInput registers 2n, 2n+1reads them (FC4)
%QDnHolding registers 2n, 2n+1writes them (FC16)

Examples:

AddressModbus point
%IX0.0discrete input 0
%IX1.2discrete input 10
%QX100.0coil 800
%IW3input register 3
%QW7holding register 7
%ID50input registers 100-101
%QD50holding registers 100-101
  • 32-bit values are low word first. A REAL travels as its IEEE 754 bit pattern across two registers, with no scaling; a DINT the same way.
  • One register, one value. A word inside a double word (%IW101 and %ID50) is a conflict; the wiring check reports it before Play.
  • Bytes (%IB), 64-bit values (%IL) and memory (%M) are not sent.

4. The simulator as a Modbus TCP client

In the dialog this is "The simulator polls the PLC". A PLC's Modbus server device exposes its process image as registers. The simulator writes holding registers (the PLC's inputs) and reads input registers (its outputs). A bit is a bit of the register that holds its byte, so a bit and that word clash. The two base settings say which %IW and %QW the device's register 0 is.

AddressRegister, from the baseThe simulator
%IXb.nHolding register b div 2, bit (b mod 2)×8 + nwrites it (FC16)
%IWnHolding register nwrites it (FC16)
%IDnHolding registers 2n, 2n+1writes them (FC16)
%QXb.nInput register b div 2, bit (b mod 2)×8 + nreads it (FC4)
%QWn / %QDnInput register(s), as abovereads them (FC4)

Examples, with both bases at 0:

AddressRegister
%IX0.0holding register 0 bit 0
%IX1.3holding register 0 bit 11
%QX0.0input register 0 bit 0
%IW2holding register 2
%ID1holding registers 2-3

The simulator moves the whole holding block with one FC16 and reads the whole input block with one FC4 per cycle, split past 123 and 125 registers.

5. Where Assign I/O puts addresses

Simulation > Assign I/O Addresses gives every tag a part is wired to by name an address, declares it in the program, and rewires the parts, as one undo step. The same scene always gets the same addresses, skipping any already taken. When the PLC polls the simulator, the first of each size is:

A tag that isTypeFirst address
published by a part (a sensor)BOOL%IX0.0
read by a part (a motor)BOOL%QX0.0
published by a partINT%IW0
read by a part (a speed)REAL%QD50

Double words start at %ID50, registers 100 and up, so a hundred words fit below them. When the simulator polls the PLC instead, points are packed from the device's first register up, each at the first free spot. A constant, and anything that cannot travel, are left alone, each reported with the reason.

6. Timing and the watchdog

WhatValue
Silence after which the PLC's outputs are held off1000 ms
How often the simulator polls a PLC, in every mode where it connects to one20 ms
How long it waits for an answer500 ms
How often it retries a PLC that is not there1000 ms
  • When the PLC goes quiet, every tag it drives is set OFF (a coil false, a register 0) and the line coasts to a stop; the run continues, and the PLC's values come back the moment it answers.
  • The watchdog is not armed before the first poll. Until the PLC has connected once, the status line says what it is waiting for instead.
  • An OPC UA server, or a TwinCAT runtime over ADS, can hide a stopped program. Each belongs to the runtime and keeps answering with the last values; only a lost connection or a silent server trips the watchdog.
  • A real PLC scans on its own clock, so Play starts at 1x. Another speed can still be chosen during the run, and the speed button turns amber: the PLC's timers and reaction times no longer match the simulation's.

8. OPC UA tags by name

  • A part's tag is the PLC's name for the variable, such as Eye or Main.Eye. A NodeId written out (ns=4;s=...) is taken as it is.
  • The simulator finds each tag on Play by matching the end of every variable's path under Objects, so the folders a server puts above the program do not matter. Case is ignored and an exact spelling wins a tie. A name that fits two variables is refused, with both listed.
  • Direction comes from the parts. A tag a part publishes is written to the PLC, and one that parts only read is read from it. The PLC's variable has to allow that, and a real input that the PLC's I/O overwrites every scan usually refuses a client's write.
  • Before use, the simulator checks that a bit goes to a Boolean and a number to a numeric type, and that the access level allows the read or the write.
  • The connection is unsecured, with security policy None and an anonymous login. A server that only accepts secured clients is reported as such.
  • If the address answers as a discovery server (often on 4840), Play says ... is an OPC UA discovery server, not a PLC and names the servers it lists.

9. S7 PUT/GET

A part's address is the CPU's own: S7 memory is byte-addressed exactly as I/O addresses are, so nothing is mapped or offset. A data block address uses the S7 data-block spelling, without the %. The S7 guide has the CPU's side.

Scene tagOn the CPUTravels asThe simulator
%IX100.0I100.0BOOLwritten to the PLC
%QX100.0Q100.0BOOLread from the PLC
%IB2IB2BYTEwritten to the PLC
%QW4QW4INTread from the PLC
%ID84ID84REALwritten to the PLC
%QD8QD8DINTread from the PLC
%MX10.0M10.0BOOLwritten to the PLC
%MW20MW20INTread from the PLC
DB10.DBX0.0DB10.DBX0.0BOOLwritten to the PLC
DB10.DBD6DB10.DBD6REALread from the PLC
  • I is written and Q is read. M and a data block have no direction of their own: a tag a part publishes is written to the PLC, and one that parts only read is read from it.
  • Values are big-endian, as the CPU holds them. A double word is a DINT when the parts carry a whole number and a REAL otherwise, its IEEE 754 bit pattern with no scaling.
  • A bit is written as a bit, so the rest of its byte is left alone. Use input bytes no module occupies: the CPU copies its real input cards over the inputs every cycle.
  • Only a data block with optimized block access turned off has fixed byte offsets. The CPU refuses the addresses of an optimized block, which is how a new one is created.
  • The CPU must permit PUT/GET access from a remote partner, a setting in its configuration. While it refuses, the connection is kept and asked again once a second, and the status line says it is still waiting for the CPU.
  • Every job is cut to the PDU size the CPU agrees when it connects, and to 20 items.

Not carried, each reported in the dialog with the reason:

Scene tagWhy
%IL0A 64-bit value
DB0.DBX0.0Data blocks are numbered from 1
DB10.DBW4.1Only a bit address has a .bit

10. SLMP devices

A part's tag is the CPU's own device address. The MELSEC guide has the CPU's side. SLMP has no authentication and no encryption: use it on this machine or a test bench.

  • Hexadecimal: X, Y, B, W, SB, SW, DX and DY. Decimal: everything else. X1A is the input 0x1A; M1A is not an address. A tag reads as an address when a digit follows its letters, so Safe1 stays a program name while X0FF spells input 0xFF.
  • Every device takes the wiring's direction. X is the CPU's inputs: on a CPU with input modules at that address, the refresh overwrites what a part published every scan, so use X addresses no module occupies.
  • A bit device carries a BOOL; a register carries words. A DINT or REAL takes two registers, low word first; values are little-endian, the CPU's own byte order, with no scaling.
  • The long devices (LTS/LTC/LTN, LSTS/LSTC/LSTN, LCS/LCC/LCN, LZ) are not carried: only the extended frame names them.
  • Every request covers one device and is cut to 960 word registers or 1024 bits; a longer span goes out as several requests.
  • A refused request keeps the connection and is asked again once a second, its end code in the status line.

11. ADS tags by name

The simulator reads and writes a TwinCAT 3 PLC's variables through the TwinCAT router on its own PC, with Beckhoff's own ADS library, so TwinCAT has to be installed there. A PLC on another computer is reached through the router's routes, as TwinCAT XAE reaches it. The ADS guide has the setup.

A tag is the variable's full symbol path, starting with the program or global variable list it is declared in:

Scene tagCarried
MAIN.Eyeyes
GVL.Station.Runyes
MAIN.Lane[3]yes
Eyeno: it names no program or list
%IX0.0no: an I/O address, not a name

On Play the simulator asks the runtime for each symbol's type, and carries these:

The PLC's typeCarried
BOOL, SINT, USINT, INT, UINT, DINT, UDINT, REAL, LREALyes
LINT, ULINTno: a scene number cannot hold every 64-bit value exactly
STRING, WSTRING, a structure or arrayno: not a single bit or number
  • An enumeration or a TIME arrives as the integer it is underneath.
  • A bit goes to a BOOL and a number to a numeric type; the other way round is refused with both named.
  • Each cycle is two requests, every write in one and every read in the other.
  • The router gives up on an answer after 500 ms, so a PLC that went away never holds the simulator up.

12. The I/O list

File > Export I/O List (.csv) writes the points the scene serves, one per row, with the columns Tag,Address,Type,Direction,Modbus point,Device. Device names the part and parameter on the point; Tag is blank where the program declares nothing at that address.

File > Import I/O List… reads tag names against addresses, in any column order, comma, semicolon or tab separated, and reads its own export unchanged. A row is refused, with its line number, when its address is malformed, memory or 64-bit, contradicts the part's direction, does not fit the declared type, collides with another row, or names a tag nobody uses.
